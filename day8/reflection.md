# Course Reflection

Looking back at this course, the steepest learning curve for me was definitely wrapping my head around networking and backend architecture—specifically understanding why we even need a server, how HTTP operates in detail, and how to explore APIs, endpoints, and headers before writing a single line of front-end markup. Early on, concepts like request headers, authentication tokens, and asynchronous JSON payloads felt abstract compared to visual styling in CSS. I overcame this mental barrier by getting my hands dirty: inspecting network traffic in browser DevTools, intentionally breaking `fetch()` requests to analyze status codes, and testing endpoints directly in the console and terminal. Seeing the exact request-response lifecycle helped connect the dots, and while I am still actively learning and reinforcing these networking concepts, demystifying how the client and server communicate was an eye-opening milestone.

Reflecting on my QuickNotes capstone and the feedback I received, the primary area I would improve is client-side resilience and perceived performance. While my client handles disabled button states and display alerts well, I want to implement optimistic UI updates so note creation feels instantaneous. I also want to add client-side offline caching and retry mechanisms for spotty connections, as well as integrating the tag filtering system directly into the interactive interface instead of leaving it strictly in the architectural documentation.

Moving forward, my next step is diving into full-stack backend engineering. I plan to build custom REST APIs using Node.js and Express, configure relational databases like PostgreSQL, and explore containerization with Docker. Gaining an appreciation for system architecture, database constraints, and scalable design in this course has given me the foundation and curiosity to start building real-world, end-to-end web applications.
